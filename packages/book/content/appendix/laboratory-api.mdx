<Prose>

The Laboratory is the TypeScript package `@sicp/lab`. The Book never evaluates code itself: it sends text to the Laboratory and draws the JSON that comes back. Everything on this page is exported from the package root.

</Prose>

<Prose>

## Evaluating

| Export | What it does |
| --- | --- |
| `parse(source)` | Text to syntax tree. Throws `SourceError` with a location. |
| `evaluate(source, options?)` | Runs to completion on the calling thread and returns an `Outcome`: `done`, `error` or `budget-exhausted`. Never throws for a program's own mistakes. |
| `prepare(source, options?)` | Parses and returns a `Machine` without running it. |
| `Machine.run(maxSteps?)` | Advances at most `maxSteps` steps and returns the status; `paused` means call again. |

Options are `budget` (steps, default 100 000), `prelude` (source evaluated first in an enclosing frame), `display` (receives output lines), `draw` (receives each line drawn by `draw_line`, as a `Segment` `[x1, y1, x2, y2]`) and `hooks`.

## Inspecting

| Export | What it does |
| --- | --- |
| `processShape(source)` | Returns a `ProcessShapeSnapshot`: for each top-level statement that makes calls, the call depth at every call and return, the maximum depth, and whether the process is recursive or iterative. |
| `maxDepth(source)` | The deepest stack of pending calls in a run. |
| `createStepTracer(source)` | Hooks that record a readable log of evaluation steps, each with its frame id, source span, top-level statement index and a structured `event` (`call`, `return`, `result`, `name`, `define` or `eval`) from which the Book's animations rebuild trees, frames and call stacks. |

Inspectors attach through `MachineHooks`: `onEval`, `onCall`, `onReturn`, `onResult`, `onDefine`, `onTopLevelStatement`. A hook observes; it cannot change the result.

## Running off the main thread

| Export | What it does |
| --- | --- |
| `createLabHost({ post })` | The worker side. Handles `run`, `trace`, `check` and `cancel` requests and posts events. Jobs run in slices so that a cancel can arrive between them. |
| `LabClient` | The page side. `submit(params, onEvent)` returns a handle with `cancel()` and a `finished` promise that resolves with the terminal event. A worker that does not confirm a cancel is replaced. |

Events for a run are `started`, then any number of `display`, `draw` and `shape`, then exactly one of `done`, `error`, `budget-exhausted` or `cancelled`.

A `trace` request returns the step log in one `trace-done` event, together with the program's output and everything it drew.

A `check` request runs an exercise's hidden tests, each on a fresh run of the submission. A `value` test compares an expression's value with the expected one. A `shape` test compares an answer with the measured kind of process, recursive or iterative. A `calls` test applies a function and bounds how many times a named function is applied along the way, which is how a check tells a logarithmic process from a linear one that computes the same values. An `error` test passes when a call stops with an error, optionally one whose message contains given text, which is how a check confirms that a program refuses bad input.
