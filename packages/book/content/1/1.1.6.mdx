export const conditionals = `function abs(x) {
  return x >= 0 ? x : -x;
}

function sign(x) {
  return x > 0
    ? 1
    : x === 0
      ? 0
      : -1;
}

function is_between(x, low, high) {
  return x >= low && x <= high;
}

display(abs(-12));
display(sign(-12));
is_between(5, 1, 10);
`;

export const orderTest = `function p() {
  return p();
}

function test(x, y) {
  return x === 0 ? 0 : y;
}

test(0, p());
`;

<Prose>

So far a function does the same thing whatever it is given. To compute an absolute value we need to test the argument and act on the result. The form for that is the *conditional expression*: a predicate, a question mark, the expression to use if the predicate is true, a colon, and the expression to use if it is false.

A *predicate* is an expression whose value is `true` or `false`. Comparisons such as `x >= 0` and `x === 0` are the primitive ones. They combine with `&&` (and), `||` (or) and `!` (not). Conditionals nest on the false side to make a case analysis, as `sign` does.

</Prose>

<Example index={0} file="conditionals.sicp" source={conditionals} anim="branches">

Each function body is drawn as a decision tree. When a function is applied, the path the evaluator takes lights up and the branches it never visits fade. The `&&` in `is_between` is a gate: its right side is only reached if the left side is true.

</Example>

<Prose>

Conditionals are not ordinary operator combinations, and the difference is the point. The rule of §1.1.3 evaluates *all* operands first. A conditional evaluates its predicate and then exactly one of the two branches. The other branch is never looked at. `&&` and `||` behave the same way: `a && b` only evaluates `b` when `a` is true.

That is what makes the next program a test of evaluation order. `p` calls itself forever. Under applicative order, the argument `p()` must be evaluated before `test` is entered, so the program never finishes. Under normal order, `y` would never be needed and the answer would be 0. Run it. The step budget stops the runaway computation, and the page stays responsive while it does.

</Prose>

<Example index={1} file="order_test.sicp" source={orderTest} budget={20000} anim="order">

The same expression under both orders of the substitution model. Normal order substitutes `p()` unevaluated and never needs it; applicative order has to evaluate it first, and `p()` rewrites to `p()` forever.

</Example>

Our model of evaluation allows for applications whose function expression is a compound expression. Use this to describe the behaviour of `a_plus_abs_b` below. Then declare `a_minus_abs_b` in the same style, choosing between `plus` and `minus` with a conditional.

<Solution>

**Solution.** The function expression `(b >= 0 ? plus : minus)` is evaluated like any other: its value is one of the two functions, which is then applied to `a` and `b`. So `a_plus_abs_b` adds `b` when it is non-negative and subtracts it otherwise, which is *a* + |*b*|. For *a* − |*b*|, swap the two branches.
