<Prose>

In using `sum` as in §1.3.1, it seems terribly awkward to declare trivial functions such as `pi_term` and `pi_next` just so we can use them as arguments. It is more convenient to say directly "the function that returns its input incremented by 4". A *lambda expression* does that:

```js
x => x + 4
```

and "the function that returns the reciprocal of its input times its input plus 2" is

```js
x => 1 / (x * (x + 2))
```

A lambda expression has parameters, an arrow, and a body, and its value is a function. The only difference from a function declaration is that the function is not bound to any name. Then `pi_sum` needs no helpers at all:

```js
function pi_sum(a, b) {
  return sum(x => 1 / (x * (x + 2)), a, x => x + 4, b);
}
```

In fact a function declaration is just a convenient way to write a constant declaration whose value is a lambda expression: `function plus4(x) { return x + 4; }` and `const plus4 = x => x + 4;` both make a function and bind `plus4` to it. And like any expression that has a function as its value, a lambda expression can be applied directly, without ever being named.

</Prose>

<Example index={0} file="lambda.sicp" source={lambdaProgram} anim="frames">

`plus4` is a constant whose value happens to be a function. The last statement applies a lambda expression in place: the frame it gets binds `x`, `y` and `z` exactly as a named function's would.

</Example>

<Prose>

Another use of lambda expressions, and of declarations inside a body, is to give names to intermediate values. Suppose we wish to compute *f*(*x*, *y*) = *x*(1 + *xy*)² + *y*(1 − *y*) + (1 + *xy*)(1 − *y*). It is clearer to name *a* = 1 + *xy* and *b* = 1 − *y* and write *f* = *xa*² + *yb* + *ab*. Constant declarations inside the function body do this, and the names `a` and `b` are local to the body, just as parameters are local to a function.

</Prose>

<Example index={1} file="local_names.sicp" source={localNamesProgram} anim="frames">

Applying `f` makes a frame for `x` and `y`. Because the body declares names of its own, the evaluator also makes a frame for the body, inside the first, where `a` and `b` are bound. Their initialisers can use `x` and `y`, found one frame out.

</Example>

<Prose>

Sometimes the steps of a function do not fit one return expression. The *conditional statement* chooses between two blocks of statements. Its predicate is in parentheses after `if`, and each branch is a block in braces, which may declare its own constants:

</Prose>

<Example index={2} file="expmod_if.sicp" source={conditionalStatementProgram} anim="calls">

The `expmod` of §1.2.6, written with a conditional statement. In the even case, a constant names the half power, which is then squared, so each level of the call tree makes a single recursive call rather than two.

</Example>

<Prose>

A conditional statement's branches are statements, so each needs its own `return`. A conditional expression has expressions for branches and is itself an expression, which is why it can be returned, passed as an argument, or nested; both forms only ever evaluate one of their branches.

</Prose>

<UnderTheHood file="packages/lab/src/syntax/parse.ts">

`parse.ts` recognises a lambda expression by looking ahead from a name or a parenthesis to the `=>`, and it records the declared name on a lambda that initialises a constant, so `plus4` shows up under its own name in traces. The evaluator scans a block for declarations and, only if it finds some, gives the block a frame of its own, which is the second frame in the picture above. The test `chapter-1/abstractions.test.ts` asserts that the in-place application gives 12, that `a` and `b` are declared in a frame inside the call frame, and that `expmod(3, 13, 13)` is 3.

Suppose we declare the function `f` below. Then `f(square)` is 4, and `f(z => z * (z + 1))` is 6. What happens if we (perversely) ask the interpreter to evaluate the application `f(f)`? Work it out with the substitution model before running it. Record the value that the evaluator finally tries to use as a function, and the argument it tries to give it.

<Solution>

**Solution.** `f(f)` substitutes `f` for `g` in `g(2)`, giving `f(2)`. That substitutes 2 for `g`, giving `2(2)`. The number 2 is not a function, so the evaluator stops with "Cannot apply 2: it is not a function".
