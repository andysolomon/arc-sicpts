<Prose>

A function is a static description. A *process* is what happens when the function runs: the sequence of deferred operations, the memory they occupy, the time they take. Two functions can compute the same value and generate processes of completely different shape.

Consider factorial. The first version below says `n * factorial(n - 1)`: it cannot finish its multiplication until the recursive call returns, so each call leaves a pending operation behind. The chain of pending multiplications is the process. It grows to depth *n* and then collapses.

The second version keeps a running product and a counter. Nothing is deferred. At every step the three names in the call fully describe where the computation stands, so the process runs in constant space even though the function calls itself.

</Prose>

<Exercise id="1.9">

Each of the two `plus` functions below adds positive integers using only `inc` and `dec`. Decide whether each generates a recursive or an iterative process, then make your answer checkable: `classify(plus_a)` should return `"recursive"` or `"iterative"`, and likewise for `plus_b`.

<Solution>

**Solution.** `plus_a` defers an `inc` on every call, so pending operations accumulate: recursive. `plus_b` passes the updated state forward with nothing pending: iterative. The checker verifies this by measuring depth with `inspect/processShape` rather than inspecting your string.

<Exercise id="1.10">

The function `A` below computes Ackermann's function. Work out by hand the values of `A(1, 10)`, `A(2, 4)` and `A(3, 3)`. Then describe `A(1, n)` for positive `n` as a formula: complete `g` so that it computes the same value without calling `A`.

<Solution>

**Solution.** `A(0, n)` doubles. `A(1, n)` unfolds to `A(0, A(1, n - 1))`, a doubling applied *n* − 1 times to 2, which is 2ⁿ. `A(2, n)` in turn applies "2 to the power of" repeatedly, giving a tower of *n* twos; `A(2, 4)` is 2 to the 16th. `A(3, 3)` reduces to `A(2, 4)`.

</Solution>
