<Prose>

Consider computing the exponential of a number: given a base *b* and a non-negative integer exponent *n*, compute *b*ⁿ. The recursive definition *b*ⁿ = *b* · *b*ⁿ⁻¹, *b*⁰ = 1 translates into `expt` below, a linear recursive process with Θ(*n*) steps and Θ(*n*) space. As with factorial, an iterative version keeps a running product and needs Θ(*n*) steps but only Θ(1) space:

```js
function expt(b, n) {
  return expt_iter(b, n, 1);
}

function expt_iter(b, counter, product) {
  return counter === 0
    ? product
    : expt_iter(b, counter - 1, b * product);
}
```

We can do much better by *successive squaring*. To compute *b*⁸, instead of multiplying by *b* seven times, square three times: *b*² = *b* · *b*, *b*⁴ = (*b*²)², *b*⁸ = (*b*⁴)². In general, *b*ⁿ = (*b*<sup>n/2</sup>)² when *n* is even, and *b*ⁿ = *b* · *b*ⁿ⁻¹ when it is odd. That is `fast_expt`. Every call with an even exponent halves the problem; an odd exponent becomes even after one more call.

</Prose>

<Example index={0} file="expt.sicp" source={exptGrowthProgram} anim="growth">

`expt` and `fast_expt` measured at *n* = 8, 16, 32 and 64. Every time *n* doubles, `expt` makes twice as many calls; `fast_expt` makes three more, one for the halving and two for the `is_even` and `square` it calls. Try *n* = 1000 for both.

</Example>

<Prose>

The process generated by `fast_expt` grows logarithmically with *n* in both space and number of steps. Computing *b*²ⁿ takes only one more multiplication than *b*ⁿ, so the number of multiplications for exponent *n* grows about as fast as the logarithm of *n* to the base 2: Θ(log *n*). The difference between Θ(log *n*) and Θ(*n*) becomes striking as *n* grows. `fast_expt` for *n* = 1000 needs only 14 multiplications.

Watch where the pending work goes when `fast_expt(2, 10)` is rewritten by the substitution model. The exponent is halved or decremented at each call, and what is left behind is a short chain of `square` and `2 *` waiting for their arguments.

</Prose>

<Example index={1} file="fast_expt.sicp" source={fastExptProgram} anim="process">

The pending chain is `square(2 * square(square(2 * 1)))`: one entry per halving or decrement, five in all for an exponent of 10, where `expt` would leave ten multiplications pending.

</Example>

<Prose>

The iterative version of successive squaring is less obvious, and the first exercise asks for it. Its key is an *invariant quantity*: a value that stays unchanged from state to state. Choosing the right invariant is a powerful way to think about the design of iterative algorithms, and the exercises after it use the same idea for multiplication and, surprisingly, for Fibonacci numbers.

</Prose>

<Exercise id="1.16">

Design a function that evolves an iterative exponentiation process that uses successive squaring and a logarithmic number of steps, as does `fast_expt`. Keep, along with the exponent *n* and the base *b*, an additional state variable *a*, and define the state transformation so that the product *a* · *b*ⁿ is unchanged from state to state. At the beginning *a* is 1, and the answer is the value of *a* at the end.

<Solution>

**Solution.** When *n* is even, (*b*²)<sup>n/2</sup> = *b*ⁿ, so squaring *b* and halving *n* keeps *a* · *b*ⁿ fixed. When *n* is odd, move one factor of *b* into *a*: (*a* · *b*) · *b*ⁿ⁻¹ = *a* · *b*ⁿ. When *n* reaches 0, the invariant says *a* · *b*⁰ = *a* is the answer.

</Solution>
</Exercise>
<Exercise id="1.17">

The `times` function below multiplies by repeated addition, in a number of steps linear in `b`. Suppose the language also had `double`, which doubles an integer, and `halve`, which divides an even integer by 2. Using these, design `fast_times`, a multiplication function analogous to `fast_expt` that uses a logarithmic number of steps.

<Solution>

**Solution.** Replace squaring by doubling: *a* · *b* = 2(*a* · *b*/2) when *b* is even, and *a* + *a* · (*b* − 1) when it is odd. This is the structure of `fast_expt` with multiplication replaced by addition throughout.

</Solution>
</Exercise>
<Exercise id="1.18">

Using the results of the two previous exercises, devise a function that generates an iterative process for multiplying two integers in terms of adding, doubling and halving, and uses a logarithmic number of steps. This is the "Russian peasant method" of multiplication, which is far older than computers.

<Solution>

**Solution.** The invariant is *acc* + *a* · *b*. When *b* is even, double *a* and halve *b*; when it is odd, add *a* to *acc* and decrement *b*. When *b* reaches 0, *acc* is the product.

</Solution>
</Exercise>
<Exercise id="1.19">

There is a clever algorithm for computing Fibonacci numbers in a logarithmic number of steps. The transformation *T* of `fib_iter`, *a* ← *a* + *b*, *b* ← *a*, is the special case *p* = 0, *q* = 1 of a family *T*<sub>pq</sub>: *a* ← *bq* + *aq* + *ap*, *b* ← *bp* + *aq*. Show that applying *T*<sub>pq</sub> twice has the same effect as applying a single *T*<sub>p′q′</sub> of the same form, and compute *p*′ and *q*′ in terms of *p* and *q*. That gives a way to square the transformation, and so to compute *T*ⁿ by successive squaring. Complete `p_prime` and `q_prime`.

<Solution>

**Solution.** Apply *T*<sub>pq</sub> to (*a*, *b*) and then again, and collect terms: the result has the same form with *p*′ = *p*² + *q*² and *q*′ = 2*pq* + *q*². `fib(1000)` then needs about 17 calls of `fib_iter` instead of 1000.

</Solution>
</Exercise>
